**Pretraining** 
Internet document simulator (base model)
1. download & preprocess Internet (fineweb from hugging face)
    - starting point : data from CommonCrawl
     - URL filtering
     - Text filtering
     - language filtering
     - extra
 2. Tokenization : converting between raw text and sequence of tokens(symbols)
     - Decrease length of sequence and increase symbol size
     - 100,277 tokens for GPT-4
     - tiktokenizer.vercel.app
3. Neural network training
     - model statistical relationship of tokens following each other in a sequence
     - pick random window of tokens (sequence of tokens)
         - window size could be between 0<< max
         - the window of tokens is called context 
    - the input to neural net is the context
    - the output of neural net is prediction of next token 
         - Output: 100,277 tokens with their probabilities for GPT-4
    - ground truth are the actual next token that we know from our data
    - parallel processing of token windows during training
    - generate new next tokens with the model in inference time and sample from output distribution for each output token
    
**Postraining** (supervised fine tuning): 
assistant model (Q&A)
-  Train the model on conversation datasets (generated by human labelers based on labeling instructions)
-  conversations are converted into sequence of tokens with special tokens for start/end and user/assistant 
- trained on sequence of tokens like in pretraining


**Hallucination** : 
the model make up information
- even if the model is not familiar in its knowkedge with a questiin it will immitate the training set style and make up answers
- to fix this issue we need conversations in our training data which the answer is "it does not know the answer" but only uses this style if the model actually does not know the answer but how?
     - 1. Use model interrogation to check what the model actually knows. If it does not know something, add refusals to its training data.
     - 2. Allow the model to search by introducing tools ( e.g. web search)
         - define special tokens for each tool
         - web search:  <search_start>the query <search_end> [...]
         - in inference when it sees this special token like <search_end> it pauses generating from the model (generating next token) and goes start a session with for example bing.com, enter the search query and copy all the text from results Inside [...]
         - so this copied text is now in the context window of the model and the model can easily reference it in its answer
         - we need training examples with these special tokens to show the model how to use the search tool
         
  **Note**: knowledge in the parameters of the model are vague collections but the knowledge in tokens of the context window is actually the working memory of the model

**Self knowledge**:
     - the model is stateless, every conversation it starts from scratch so does not know aything about itself
     - the way to add this knowledge 
          - through system messages at the beginning if conversations, which are invisible info in context window
          - through training data with the content for the assistant info (role: assistant, content: My name is Chatgpt a model developed by OpenAI)

**Models need tokens to think**:
Distribute the computation across many tokens, means ask model to produce intermediate results, Not just the last result in just one token
Like the response with the end math result at first and computations at the end is a very bad LLM response.
The intermediate results help the model to slowly comes to the answer.
If the model respond the result at first you are training the model to somehow guess the end result in a single token so it is less reliable.

*Note: Models are not good at counting,
Models are not good at spelling, since they see tokens not characters.
     - How many "r" is in Strawberry ?


#### **Reinforcement learning**: 
We are given the problem statement (prompt) and the final answer. We want to practice solutions that take us from problem statemet to the answer and internalize them into the model.
Generate many solutions for each prompt, from the correct solutions pick top ones and train the model on them and repeat.

##### Naive approach
Run updates as usual, of 1000 updates of 1000 prompts of 1000 rollouts
(Cost: 1000000000 scores from humans)

##### RLHF approach (RL with human feedback)
Step 1 :
Take 1000 updates, get 5 rollouts, order them from best to worst (cost: 5000 scores from humans)
Step 2: 
Trsin a neural net simulator of human preferences( reward model)
Step 3:
Run RL as usual but use simulator instead of actual humans
